## Highlights

- Export audio-only clips as MP3, M4A/AAC, Ogg/Opus, FLAC, or WAV. The editor and converter share Video, Audio, and GIF controls, remember independent format preferences, and support cancellation and retry. Encoding stays in your browser.
- Create, edit, and delete your own subtitles on local videos or provider media, even without a source subtitle track. Start blank or import dialogue, preview text as you type, and undo or redo subtitle changes. Authored text appears in previews, frame grabs, and video exports.
- See Plex and Jellyfin playback sessions update automatically when playback starts, pauses, or stops. Disconnected sources retain their last snapshot with a visible connection status, reconnect automatically, and offer **Retry connection**.
- Preserve source details, artwork, credits, and millisecond clip timing across supported video and audio containers. Local-file exports now receive clip timing even without provider metadata.
- Use more reliable Plex media, audio-track, and subtitle selection through generated API contracts, with stricter resource-link and credential handling. This release also updates dependencies to address known security advisories.

## Breaking changes and upgrade notes

**Finish or export existing browser drafts before upgrading.** Subtitle authoring uses draft version 2. Previous saved clip ranges, subtitle edits, deletions, visibility, and provider-track selections are not restored, and there is no migration. Provider media may import its preferred supported subtitle track again; local videos start with an empty subtitle lane. Original media, exported files, provider subtitle sources, and shared subtitle style preferences are unaffected.

**Regular Jellyfin accounts require Jellyfin 10.11 or newer for live session updates.** Older servers require an administrator account. There is no polling fallback. Plex session discovery still requires a server administrator account.

**Reverse proxies must support persistent notification connections.** Allow WebSockets between Cliparr and Jellyfin, and unbuffered server-sent events between Plex and Cliparr and between Cliparr and the browser. Review [reverse-proxy configuration](https://cliparr.dev/docs/configuration#reverse-proxies) if updates are delayed or connections repeatedly drop.

**Plex playback and subtitle handling is stricter.** Downloads require provider-returned part links. Conflicting media or part identities can suppress previews and subtitle extraction, and unidentified streams no longer inherit selection or track numbers from their array positions. Unsupported raw Plex subtitle resources, including external ASS/TTML, are excluded from import; supported local-stream VTT conversion and embedded subtitle extraction remain available. Undocumented Plex response aliases and `Network` export tags have been removed.

**Export metadata consumers must use the versioned payload.** The custom `clpr` tag now contains version 1 JSON with `source` and `clip` objects, replacing the previous unversioned shape. Other supported containers carry the same payload as `CLIPARR_METADATA`. No legacy payload aliases are written; individual MP4 timing tags remain available. See [export metadata](https://cliparr.dev/docs/export-metadata).

**Stereo mixdown is enabled by default for exports containing audio.** Mono remains mono. Identified surround layouts include dialogue and surround contributions, omit LFE, and use headroom that can make the result quieter than older exports. Disable **Mix down to stereo** to preserve supported channel layouts. MP3, WAV, and native Opus output currently require mono or stereo; unsupported layouts produce an explanation instead of silently dropping channels.

For integrations built from source, export callers must replace `includeAudio` with export mode and mixdown preferences and use the shared format API. Plex callers must use generated `@cliparr/plex` operations and URL builders. No compatibility aliases or fallback implementations are provided. The website also moves to Astro 7 and Vite 8; rebuild deployed artifacts with the updated lockfile.

## Audio export limitations

Some FLAC boundaries, including single-frame clips and very small final compressed frames, are unsupported by the current media library. Cliparr rejects affected exports before download; choose WAV or adjust the clip boundaries. Standalone FLAC input selections with an unreadable tail are also rejected. Audio is not padded or retimed to work around these limitations.

Exports remain in browser memory. Large audio exports show memory guidance, and WAV has a 4 GiB file-size limit. See [export settings](https://cliparr.dev/docs/export-settings) for browser codec, channel, and bit-depth support.
