## Non-root distroless production images

Cliparr’s amd64 and arm64 production images now use Google’s distroless Node.js 26 runtime on Debian 13. The images leave out the shell and package manager, so there are fewer tools in the deployed container. Cliparr still runs as UID/GID 65532 and supports a read-only root filesystem. Standard Docker and Compose deployments can keep their start command, port 7171, and writable `/data` volume. The development and capture images continue to use Debian slim.

**Breaking change for custom container maintenance.** Update health checks and entrypoint overrides that call `/usr/local/bin/node` to use `/nodejs/bin/node`. Move commands that rely on a shell or package manager outside the production container. To check the runtime directly, use `docker exec <container> /nodejs/bin/node --version`. [Docker guide](https://github.com/TechSquidTV/Cliparr/blob/main/docker/README.md#production-runtime)

## Security

Cliparr now keeps provider login cookies out of server logs and removes credentials from sign-in errors. Older logs can contain active cookies even at the default log level. If you shared a log containing an active cookie, disconnect the affected provider account in Cliparr to revoke its sessions. Disconnecting also removes its saved sources. Sign in again to reconnect them. If a shared sign-in error exposed a Jellyfin password, change that password in Jellyfin. [Logging guide](https://cliparr.dev/docs/logging)

Updated dependencies to resolve ten Dependabot security alerts. Renovate now checks for compatible lockfile updates every week. [Dependency fixes](https://github.com/TechSquidTV/Cliparr/pull/340)

## Highlights

- GIF exports in the editor and Cliparr Convert round frame boundaries to 10 ms so timing errors no longer accumulate. A one-second export at 12 fps now plays for one second instead of 960 ms, and a short final frame no longer adds a visible pause. All four presets are available. Re-exporting with gifenc 2.0 can change colors, dithering, and file size.
- Plex and Jellyfin subtitle imports now allow up to two minutes for embedded text tracks. You can cancel while waiting. The subtitle menu explains why a track cannot be imported, including image-based PGS and VobSub tracks or an embedded text track that must first be selected in Plex.
- Jellyfin now uses the source’s default subtitle track when the player has no selection. Subtitle downloads use the resolved media source, and playback logs give more detail when a track cannot be found.
- Slow provider sign-ins complete once, and cancelling a sign-in prevents a late response from connecting the account.
- Reopening export settings reuses recent HLS metadata for file-size estimates. Saving editor drafts, finding a free range for a new subtitle, and sending GIF frames to workers also do less repeated work.

## Website and maintenance

- The homepage shows how to open a clip at the current Plex or Jellyfin playback position. The 3.1 announcement, README, and guides illustrate mobile editing and cropping with refreshed captures. The homepage phone preview is now recorded at 3× display density for sharper text.
- The editor shares HLS source detection between playback and export setup, and uses one width-and-height type across preview, crop, export, and Cliparr Convert.
